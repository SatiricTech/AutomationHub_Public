The M365 Migration Toolkit is seventeen PowerShell scripts plus a shared module for a tenant-to-tenant migration. AvePoint Fly moves mailboxes, archives, OneDrive, SharePoint, Teams and M365 Groups; this toolkit designs and provisions destination identities, licenses users, recreates mailbox delegation, releases the source domain and verifies the result. Code: github.com/SatiricTech/AutomationHub_Public — Utilities/M365-Migration — pull the whole folder (every script imports the M365Migration module beside it); see its README.md for the full parameter reference, auth matrix and plan schema.

Prerequisites

  • PowerShell 7.4 or later, Windows or macOS.
  • Microsoft.Graph.Authentication, ExchangeOnlineManagement (v3+), MicrosoftTeams (5.7.0+) and ImportExcel — auto-installed for the current user on demand.
  • A dedicated Global Admin signed in directly to each tenant, pinned with -TenantId — User Administrator (Privileged Authentication Administrator for another admin), Exchange Administrator, Teams Administrator, Domain Name Administrator for domain release, SharePoint Administrator only for OneDrive pre-provisioning.
  • Fly is authorised by app consent from a Global Admin in each tenant once the tenants are connected in the Fly console. A service account is optional — only needed if a specific Fly module asks for one.
  • GDAP alternative: a partner administering a tenant through GDAP passes -DelegatedOrganization <customer>.onmicrosoft.com to the Exchange-writing scripts instead of signing in as a Global Admin in it.
Read the tenant line, and dry-run first

Every script prints the tenant id and display name it actually connected to — read that line before you let any writer run. A stale cached session, or a GDAP connect made without -DelegatedOrganization, lands you in the wrong tenant.

Every writer accepts -DryRun: evaluates every row, writes a results file with Status Planned, changes nothing — dry-run everything first. Two exceptions: Get-MigrationInventory -DryRun writes only the log, no results CSV; Test-MigrationReadiness's checks are already read-only, so -DryRun there just suppresses the Provisioned-stage plan writeback and the OneDrive-provisioning read.

The runbook

<ts> below stands for the run's timestamp. -PlanPath resolves a wildcard when it matches exactly one file (error otherwise); every other CSV path is read literally — substitute the real file name for those.

  1. Inventory both tenants — read-only. 
    .\Get-MigrationInventory.ps1 -Prefix Source -TenantId contoso.onmicrosoft.com -IncludeAuthMethods
.\Get-MigrationInventory.ps1 -Prefix Destination -TenantId newco.onmicrosoft.com

    Check: nine CSVs per tenant, Summary counts match the admin center. Count MfaRegistered = True in the Users tab.

  2. Build the identity plan — offline, no tenant connection. 
    .\New-MigrationIdentityPlan.ps1 -UsersCsv .\Source_Users_<ts>.csv `
    -UserMailboxesCsv .\Source_UserMailboxes_<ts>.csv `
    -SharedMailboxesCsv .\Source_SharedMailboxes_<ts>.csv `
    -GroupsCsv .\Source_Groups_<ts>.csv -ContactsCsv .\Source_Contacts_<ts>.csv `
    -TargetDomain newco.com -InterimDomain newco.onmicrosoft.com -UpnFormat First.Last `
    -ReservedAddressesPath .\Destination_Users_<ts>.csv -Prefix Contoso

    Check: zero Invalid rows; every NeedsReview/ Collision row fixed and marked ManualOverride. Send the plan for client sign-off.

  3. Export the Fly mapping file — offline. 
    .\Export-MigrationMappingFile.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv `
    -Tool AvePoint -UseInterim -Prefix Contoso

    Check: no unexpected Skipped rows.

  4. Readiness — stage Pre. 
    .\Test-MigrationReadiness.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Stage Pre `
    -TenantId newco.onmicrosoft.com -Prefix Contoso

    Check: exit code 0 before you provision anything.

  5. Fly console: create the project and connect both tenants. Grant Fly app consent per tenant, connect them, upload the mapping file from step 3.

    Check: both tenants connected, mapping accepted, no unmatched rows.

  6. Provision the destination users. 
    .\New-MigrationUsers.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Wave 1 -UseInterim `
    -HideFromAddressLists -SetManagers -TenantId newco.onmicrosoft.com -Prefix Contoso -DryRun

    Check: drop -DryRun once the results file looks right; every row Succeeded, plan now carries TargetObjectId. Passwords are in the results CSV only — secure it immediately.

  7. Licence them. 
    .\Set-MigrationLicenses.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Wave 1 `
    -DefaultUsageLocation US -TenantId newco.onmicrosoft.com -Prefix Contoso

    Check: seat pre-check shows no shortfall. Group-assigned SKUs are skipped — fix by changing group membership.

  8. Create mail recipients. 
    .\New-MigrationRecipients.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Wave 1 `
    -Mode CreateAndUpdate -GroupsCsv .\Source_Groups_<ts>.csv `
    -ContactsCsv .\Source_Contacts_<ts>.csv -SharedMailboxesCsv .\Source_SharedMailboxes_<ts>.csv `
    -TenantId newco.onmicrosoft.com -Prefix Contoso

    Check: unmapped members/owners (usually ex-employees) reported per row, not fatal. -Mode UpdateSettings alone patches groups Fly already created.

  9. Readiness — stage Provisioned. 
    .\Test-MigrationReadiness.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Stage Provisioned `
    -SourceMailboxesCsv .\Source_UserMailboxes_<ts>.csv -TenantId newco.onmicrosoft.com `
    -Prefix Contoso

    Check: mailbox, archive, hold off, OneDrive provisioned, quota not below source. Writes MailboxProvisioned/OneDriveProvisioned back to the plan.

  10. Fly console: run the pre-cutover content jobs. Mailboxes, archives, OneDrive, SharePoint, Teams, M365 Groups; re-run deltas until each pass is quick.

    Check: delta passes stay small, errors don't grow. Chase recurring per-item failures before cutover.

  11. Release the vanity domain in the source tenant. Report first. 
    .\Remove-MigrationDomainReferences.ps1 -Domain contoso.com -ReportOnly `
    -TenantId contoso.onmicrosoft.com -Prefix Contoso

.\Remove-MigrationDomainReferences.ps1 -Domain contoso.com -AcknowledgeSourceTenant `
    -TenantId contoso.onmicrosoft.com -Prefix Contoso

    Check: the remediation run exits 0 and _DomainBlockers-Recheck_<ts>.csv holds only the "no rows" entry — not a -ReportOnly exit code or an empty pre-remediation Blockers CSV. Then remove the domain and verify it in the destination.

  12. Cutover day: mail flow. Change MX to the destination tenant; update SPF, DKIM, DMARC and any mail-filter connectors.

    Check: test message in and out before touching identities.

  13. Apply the target identities. 
    .\Set-MigrationIdentity.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Wave 1 `
    -Apply Upn,PrimarySmtp,Aliases,X500,MailNickname,GalVisibility -Unhide `
    -MatchOn TargetObjectId -TenantId newco.onmicrosoft.com -Confirm:$false -Prefix Contoso

    Check: -Confirm:$false is needed (High ConfirmImpact prompts per object otherwise). Spot-check three users: UPN, primary SMTP, aliases, X500, unhidden. Directory-synced rows report Failed — fix on-premises.

  14. Re-apply mailbox delegation. 
    .\Set-MigrationMailboxPermissions.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv `
    -MailboxPermissionsCsv .\Source_MailboxPermissions_<ts>.csv `
    -UserMailboxesCsv .\Source_UserMailboxes_<ts>.csv `
    -SharedMailboxesCsv .\Source_SharedMailboxes_<ts>.csv `
    -Apply FullAccess,SendAs,SendOnBehalf,Calendar,Forwarding -Wave 1 -Confirm:$false `
    -Prefix Contoso

    Check: -Confirm:$false again (same High ConfirmImpact). Review Skipped rows — an unmapped trustee means a service-desk call. Safe to re-run; existing grants report already present.

  15. Reset cutover passwords. 
    .\Reset-MigrationCutoverPasswords.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Wave 1 `
    -TenantId newco.onmicrosoft.com -Confirm:$false -Prefix Contoso

    Check: -Confirm:$false — High ConfirmImpact, per-user prompt. One passphrase per user, flagged to change at next sign-in. Distribute out of band, never by email to that tenant.

  16. Teams Phone. Release in the source, reassign in the destination once the port completes — start the port weeks ahead, it gates cutover. 
    .\Get-MigrationTeamsPhoneAssignments.ps1 -Prefix Source -TenantId contoso.onmicrosoft.com -IncludeUnassignedNumbers
.\Remove-MigrationTeamsPhoneAssignments.ps1 -CsvPath .\Source_TeamsPhoneAssignments_<ts>.csv `
    -TenantId contoso.onmicrosoft.com -Confirm:$false -Prefix Source
.\Set-MigrationTeamsPhoneAssignments.ps1 -ListUnassigned -TenantId newco.onmicrosoft.com -Prefix Destination
.\Set-MigrationTeamsPhoneAssignments.ps1 -CsvPath .\Source_TeamsPhoneAssignments_<ts>.csv `
    -TenantId newco.onmicrosoft.com -Confirm:$false -Prefix Destination

    Check: -ListUnassigned (no changes, no prompt) confirms the numbers arrived before reassigning; the other two live commands need -Confirm:$false (High ConfirmImpact). Users need a Teams Phone licence; hybrid on-prem numbers report Failed.

  17. Viva Learning history (optional). 
    .\Get-MigrationVivaLearningHistory.ps1 -Prefix Source -TenantId contoso.onmicrosoft.com
.\Import-MigrationVivaLearningHistory.ps1 -CsvPath .\Source_VivaLearningHistory_<ts>.csv `
    -TenantId newco.onmicrosoft.com -ClientId <app-id> `
    -ClientSecret (Read-Host -AsSecureString 'Secret') `
    -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Prefix Contoso -DryRun

    Check: fill blank CourseTitle/CourseWebUrl cells before the real import; catalog content can take 24 hours to appear.

  18. Readiness — stage Post. 
    .\Test-MigrationReadiness.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv -Stage Post `
    -TenantId newco.onmicrosoft.com -Prefix Contoso

    Check: exit code 0 — UPN, primary SMTP, every alias, X500, unhidden, enabled.

  19. Compare. Re-inventory the destination and diff it against the plan. 
    .\Get-MigrationInventory.ps1 -Prefix Post -TenantId newco.onmicrosoft.com
.\Compare-MigrationUserData.ps1 -PlanPath .\Contoso_IdentityPlan_<ts>.csv `
    -DifferenceCsv .\Post_Users_<ts>.csv -Prefix Contoso

    Check: every plan row Match — anything else didn't make it, cheaper to find now than in a week.

Identity plan decisions

Interim domain. The vanity domain can only live in one tenant at a time, so provision on newco.onmicrosoft.com first with New-MigrationUsers -UseInterim, then apply the real Target* addresses with Set-MigrationIdentity once the domain has moved. Omit -InterimDomain only when the domain is already in the destination, or for an in-place redesign.

UPN is not the primary SMTP. -SmtpFormat defaults to -UpnFormat, so they usually match. Setting it separately produces a user who signs in as jsmith@newco.onmicrosoft.com but receives mail as john.smith@newco.com — flagged UpnSmtpDiverge deliberately, so the service desk knows the sign-in address is not the mailbox address.

In-place UPN redesign. The same tooling standardises addressing inside one tenant, no second tenant: inventory it, run New-MigrationIdentityPlan against its own export with its own domain as -TargetDomain and no interim domain, review the plan, then apply with Set-MigrationIdentity -MatchOn Source — the objects already exist, so Source* is today and Target* the new scheme. The old primary stays as an alias unless -RemoveOldPrimaryAlias; add -Confirm:$false or it prompts per operation.

Troubleshooting

SymptomFix
Replies to old mail bounce with an IMCEAEX NDR LegacyExchangeDN never stamped as X500 — run Set-MigrationIdentity -Apply X500
assignLicense fails, "invalid usage location" Set UsageLocation in the plan, or pass -DefaultUsageLocation
A licence will not come off, or comes back doubled Group-assigned. Set-MigrationLicenses skips both directions — change group membership
User create or UPN rename returns 409 "already exists" A soft-deleted user holds the address. Test-MigrationReadiness -Stage Pre lists it — purge or restore
403 Authorization_RequestDenied on one account Target holds an admin role — use Privileged Authentication Administrator
"Out of the current user's write scope"; row reports Failed Directory-synced object — change on-premises, let AAD Connect sync
Still visible in the GAL despite New-MigrationUsers -HideFromAddressLists Graph's showInAddressList loses to Exchange once mailboxed — re-apply Set-MigrationIdentity -Apply GalVisibility
Domain will not delete from the source tenant Remove-MigrationDomainReferences -ReportOnly lists references plus blockers. Guest #EXT# UPNs are informational
A Teams number will not release from the source tenant Hybrid, synced on-premises (OnPremLineURI) — clear it there; the script reports Failed
Script says a CSV or plan file was not found though it exists Only -PlanPath resolves a unique wildcard; every other CSV path is literal — pass the exact file name
